# P22 实验报告 — 固化状态表示 vs 烘烤身份对照

**结论先行**：P22 是负结果。`cure_state = cure_drive + cure_margin_eff` 在分布内只提高 `+0.009007` QWK，低于预注册 `+0.010`，且只有 12/20 seeds 正向；单独一个 `bake_control` 二元烘烤指示反而达到 `+0.012458`。在 leave-one-condition-out 下，`cure_state` 从 `0.463109` 崩到 `0.327897`（`−0.135212`），说明这两个“固化状态”变量主要是在编码烘烤条件，而不是可迁移的固化机理。C1/C2 均失败；C3 placebo 通过，但只是 supporting，不能升级为可部署 claim。

**日期**：2026-11-28

## 协议

- 301 条实测 T，标签 `33/197/71`，cuts `[15,20]`，`formula_id` 301 组。
- 191 维 raw `full8` = 183 base + 8 FTIR；沿用 P21/P20 的 `P21Prep` 和 `C=2.0` ordinal cumulative logistic。
- 5 折 `StratifiedGroupKFold` by `formula_id`；20 seeds。
- `full8_base` sanity seed 42 = `0.5761275403`，精确复现 P20 `0.576128`。
- CURE2：`cure_drive`、`cure_margin_eff`；`tg_rise_est` 只做 CURE3 探索。
- `bake_control`：`cure_205` 二元（205°C/17min=1，200°C/10min=0），与 P19 `cure_meta` 同口径。
- 所有 imputer/scaler 只在 outer training fold 拟合；shuffle 不使用 y。

## 解释

1. **C1 不是“差一点通过”**：ΔQWK `+0.009007 < +0.010`，12/20 `<14/20`，Holm p `0.20269`，HR `−2.042 < −2.0`；四个条件同时不满足。不能因为 `+0.009` 接近 `+0.010` 就移动门槛。
2. **bake 二元指示比 CURE2 更强**：`bake_control` `0.582640`，比 `cure_state` 高 `+0.003451`；`cure_state_plus_bake` 又比 `bake_control` 低 `−0.003612`。这说明 CURE2 没有提供超出烘烤身份的增量，甚至引入额外方差。
3. **C3 通过但不足以救主 claim**：`cure_state` 比同维度 shuffle 高 `+0.014604`，14/20，p `0.01530`；它确实有“非随机”的信号，但这个信号在分布内弱于一个二元烘烤指示，在 LOCO 下崩溃，不能写成可部署的固化机理。
4. **CURE3 更差**：加 `tg_rise_est` 后 `0.575539`，比 CURE2 低 `−0.003649`，4/20。保留 CURE2 作为本轮最简表示，但整条路线不采纳。
5. **P21 的负结果被进一步解释**：P21 不是“角色权重没调好”，而是 301 条 T + 两个烘烤条件里，唯一有独立方差的固化变量本身就是条件代理；继续手工加权/加特征不会产生可迁移信号。
