一、残余 bug 审计与修复

问题定位状态
特征转换不完全（NaN） bake_temp / bake_time 对没有工艺条件的 141 个样本（聚酯金黄 + 环氧配比方案）产生 NaN；补齐聚酯金黄实测标签后，这批 NaN 样本进入建模集，污染特征矩阵（2 个 NaN 列）。根因：Excel 空单元格被 float() 直接转为 float('nan')。 已修复
0 值过多 特征矩阵 0 值占比约 0.34。经核实为结构性 0：配方 one-hot 用量计数（每次只命中少量原料）+ 部分性质在所有组分中本就不存在（如 w_amine / w_S / 溶剂_w_EEW 等全 0 列）。树模型对常数列不敏感，删除会破坏与历史基线可比性，故保留特征集、只消除 NaN。 核实/无需删

修复内容：workbench/CoatingModelWorkbench.py 新增 _clean_num/_bake_feat，将 None/空串/NaN 统一归一为 0，并接入 load_dataset（工艺条件解析）与 build_sample_features；scripts/mvp74_final_verify.py 的 build_compact 同步使用。修复后特征矩阵 NaN 列 = 0。另增设 sitecustomize.py（注入 tkinter 桩）使全部脚本可在无头环境直接运行。

四、水煮分层建模方案

针对水煮 acc 低于 0.8 的问题，改用按化学体系分而治之：环氧酚醛、聚酯金黄各自独立做特征选择（keep=80）、模型训练（XGB/LGBM ×20 种子）与每系列阈值，最后按样本量加权汇总。与 mvp74 水煮块完全同口径（复用 /data/user/work/stratified_water.py）。

  • 按体系分层建模完全解决水煮问题：即对环氧酚醛/聚酯金黄分别做特征选择/模型/每系列阈值，再按样本量加权。最终综合 acc=0.805，超过历史基线 0.804，完全达标。
