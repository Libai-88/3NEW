# 数据集模板：工作原理与泛化原理（非化学人员友好版）

> 本文配合流程图阅读：[数据转换与泛化原理流程图](assets/数据转换与泛化原理流程图.svg)（浏览器打开）。
> 面向对象：项目经理、数据分析新人、非本行业人员。**不需要懂化学**，把"原料"想成"配料"，把"体系"想成"一类菜的做法"即可。

---

## 0. 用一句话说清楚

我们想做的是：**把你已经做过的真实实验数据整理成一张"标准答卷表"，让电脑模型从中学会规律，然后能对"没做过实验的新配方"提前预测性能，并且知道"哪些配方预测得准、哪些不准"。**

全程分两大块：
1. **数据怎么转**（模板工作原理）——把零散的真实记录，一步步变成模型能读的数字。
2. **模型怎么用到别处**（泛化原理）——模型学会的是"化学规律"而不是"背答案"，所以能用在没见过的配方和体系上。

---

## 1. 为什么要"模板"？为什么不能直接拿表格去训练

- 模型只能吃"**一行 = 一个样品**、**一列 = 一个数字特征**"的表格。
- 但真实记录是"配方是几号原料+多少克、性能是多少分"这类**长条记法**，还不能直接用。
- 所以模板的作用 = **一个约定好的格式 + 一套自动换算规则**，把所有来源整理成唯一的标准表。
- 好处：只要格式统一，新的实验、新的体系填进来就能一起训练，不用每次重新改程序。

模板里每个表各管一件事，靠 **样本ID** 串起来（就像超市小票号把商品、价格、支付连在一起）。

| 模板表 | 管什么 | 通俗解释 |
|---|---|---|
| 体系配置 | 每个体系要预测的"目标" | 决定这一体系到底预测"弯曲半径(T弯)"还是"MEK擦多少次"等 |
| 原料主数据 | 每种原料的"化学身份证" | 一个原料一套数字（分子量、固含、含多少活性基团…） |
| 配方明细 | 每个样品用了哪些原料、各多少克 | 长条记法；自动按原料去取"身份证"并算"贡献" |
| 性能结果 | 每个样品的实测目标值 | 弯了多少、擦了多久、水煮几级 |
| 工艺条件 | 烘烤温度/时间等 | 固化工艺（部分体系没记，模型当作"未知"处理） |
| 配方级描述符 | 每个样品的一行"总体特征" | 把整个配方聚合成一组数字 |
| 配方级机理特征 | 用化学公式算出的"配方性格" | 交联致密程度、配比是否接近化学完美点等 |
| 建模输入 | 最终给模型的宽表 | 一行=样品，列=特征+目标+标签状态 |
| 数据字典 | 每个字段什么意思 | 查字典用 |

## 2. 数据从哪里来（都是"真实数据"，不是编的）

| 来源 | 提供什么 |
|---|---|
| 配料测试数据汇总V1 | 环氧酚醛体系：配方 + 实测性能（T弯/MEK/水煮） |
| 配比方案、聚酯金黄-AI | 另两个体系的配方；并含性能记录（只带有 T弯/MEK/水煮 字样的都算同一种测试，只是不同人记录方式不同） |
| 原料送检 + TDS/SDS（291 份） | 每种原料的关键实测值出处，优先用它，避免"瞎估" |

整理后的规模（`merged_data.pkl` / `合并版数据集.xlsx`）：
- 486 个配方样品；
- 实测有标签 440 / 无标签 46；
- 三项目标实测数：T弯 354、MEK 335、水煮 218；
- 80 种原料，77 种描述符已由 TDS/SDS 实测或同族推断锚定（类别典型值的用量加权占比已降到 0）。

> 带 T弯/MEK/水煮 字样的字段视为同一种测试（同实验室、不同人书写差异）；`蒸汽煮/3%盐/2H/3H/BOX/电腐蚀/附着力` 等是**不同的测试端点**，不属于这三项目标，不强塞成数字。

## 3. 数据转换的五步（模板工作原理）

### 第 1 步：原料 → "化学身份证"（原料主数据）
- 每种原料登记一组数字：分子量、固含、当量（每多少克含一个活性基团）、Tg、元素含量、官能团密度等。
- **可信度从高到低**：TDS/SDS 实测 → 送检组成 → 公开手册值 → 同族推断 → 类别典型值。
- 关键：**建模用的是这组数字，而不是原料代号**。这是"能用到新原料"的根基。

### 第 2 步：配方 → "长条展开"（配方明细）
- 一个样品 = 若干行（每行一个原料 + 用量克数）。
- 自动按原料代码去取该原料的"身份证"，并对每个描述符算 `贡献 = 用量 × 该原料描述符`。

### 第 3 步：长条 → "一行总体特征"（配方级描述符）
- 把同一配方的贡献加起来、除以总用量，得到**质量分数加权**的特征（树脂占比、加权Tg、加权固含…）。
- 再加**官能团密度**（每 100g 配方含多少环氧基/羟基/羧基…）。
- 通俗：十种调料的配方，浓缩成"这一锅的总体味道"的一串数字。

### 第 4 步：再加"化学机理"（配方级机理特征）
- 线性平均会漏掉关键信息，所以用化学公式额外算：
  - **计量比**：环氧对羟基的比例是否接近反应完美点；
  - **交联密度 νe**：固化后网络多致密（越密通常越脆、T弯越差）；
  - **Fox 共混 Tg、固化度**（与烘烤工艺耦合）、**Hansen 相容性**、**PVC 颜料浓度**。
- 没有烘烤记录的样品，固化类机理量记"不可知(NaN)"，**不强行算成 0**（那是欺瞒，不是数据）。

### 第 5 步：组装"建模输入"宽表
- 一行 = 一个样品；列 = 描述符 + 机理特征 + 目标值 + 标签状态。
- 目标值按「体系配置」自动生成（不同体系目标不同）。
- 这张表直接进模型训练 / 预测。

```
数据源 → 原料主数据 → 配方明细 → 配方级描述符 → 配方级机理特征 → 建模输入 → 模型
（真实）   （数字身份证） （长条展开）  （一行总体特征）   （化学性格）     （标准答卷）
```

## 4. 泛化原理（模型怎么用到不同体系 / 新配方）

"泛化"= 面对没见过的数据也能给出可信结果。这套方案从四个角度保证：

1. **说人话就是"学会规律，不是背答案"**
   模型学的是"原料特征与性能的关系"，而不是记住"某号配方=多少分"。所以：
   - 新原料：只要有人给它登记"化学身份证"，就能换算出同一套数字，模型照样能用；
   - 新体系：在「体系配置」加一行即可，模板结构不用改。

2. **宁可少报，不虚报（诚实评估）**
   - **留一体系外验证(LOSO)**：把整个体系从训练里拿走，看还剩多少预测力——最能说明"换体系还行不行"。
   - **按体系分组(GroupKFold)**：同一体系的样品不会同时出现在训练和测试，防止"偷偷见过答案"。
   - **特征选择在折叠内做 + 公共噪声掩码**：所有"选哪个特征、卡在哪"的决策都不接触验证数据，杜绝虚高。
   - 结论要**按体系拆分报告**，综合值只是参考。

3. **标签不够，就"闭环补标签"**
   - 高置信（不确定度小）→ 自动伪标签，回填重训；
   - 中置信 → 推荐测试（主动学习挑最值得做的实验）；
   - 低置信 → 人工复核；
   - 迁移学习（源域预训练 + 目标域少量实测微调）实测效果最好。
   - 循环：预测 → 推荐测试 → 回填实测 → 重训 → 再看跨体系准度。

4. **诚实标注边界**
   - 某些体系（如聚酯金黄）实测样本少、水煮几乎恒定 2 级，**不能说它对水煮"有判别力"**；
   - 环氧-配比方案的 T弯 来自另一种测试口径（T弯G 腐蚀判定），开区间 `<10`/`>15` 是按配方脆性差异化赋值；
   - 全新系列先测 1~2 个配方回入，再依赖预测数值，否则数值外推不保证可用。

---

## 5. 一句话总结

> **模板 = 把真实配方与测试结果，按固定格式一步步转成模型能读的"标准数字表"；泛化 = 因为用的是"原料化学特征"而不是"代号"，加上诚实验证与补标签闭环，模型才可能把学到的规律用到没做过的配方和体系上。**

常用命令与产物：`scripts/build_merged_excel.py` 生成 `合并版数据集.xlsx`；`scripts/extract_perf_labels.py` 按同实验室字段口径补全性能；`data/merged_data.pkl` 为训练用中间数据。
